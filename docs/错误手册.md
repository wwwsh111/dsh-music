# DSH Music 错误手册（v1.0）

> 用法：先在 DSH 里把**完整报错原文**看一遍，再到下面按关键词搜。每条都写了「报错原文 → 原因 → 处理 → 可复制命令」。
> 命令默认在插件安装目录执行（即 `package.json` 所在的目录）。Windows 下把 `<安装目录>` 换成你的实际路径。

## 安装与引擎

### 1. `Python 解释器不存在：C:\Users\...\venv\Scripts\python.exe。先运行 scripts/bootstrap.sh 安装引擎依赖。`

**原因**：插件找不到 Python venv，通常是没跑过安装脚本，或 venv 被移动/删除。

**处理**：重跑 bootstrap，确认它输出的 venv 路径和你配置的一致。

```powershell
powershell -ExecutionPolicy Bypass -File ".\scripts\bootstrap.ps1"
powershell -ExecutionPolicy Bypass -File ".\scripts\doctor.ps1"
```

### 2. `音乐引擎启动失败（C:\...\python.exe）。日志尾部：...`

**原因**：引擎进程起不来。常见是端口 17890 被占、Python 依赖损坏、或日志里有 Python traceback。

**处理**：先看日志尾部，再查端口；不要反复重启 DSH。

```powershell
Get-Content "$env:USERPROFILE\.dsh\music\engine.log" -Tail 60
Get-NetTCPConnection -LocalPort 17890 -ErrorAction SilentlyContinue | Select-Object OwningProcess
powershell -ExecutionPolicy Bypass -File ".\scripts\doctor.ps1"
```

### 3. `engine HTTP 500: ...` / `engine HTTP 400: ...`

**原因**：引擎收到了请求但执行失败，冒号后面是 Python 的异常信息。400 多是参数不合法，500 多是环境或文件问题。

**处理**：把冒号后的原文对照本手册；同时看 `engine.log` 的 traceback。

```powershell
Get-Content "$env:USERPROFILE\.dsh\music\engine.log" -Tail 80
```

### 4. `engine response timeout`

**原因**：渲染/分离/人声这类长任务超过了工具等待时间；任务可能还在后台跑。

**处理**：先看工程目录里有没有新文件；人声任务用同一个 `jobId` 继续查，不要重复提交。

```powershell
Get-ChildItem "$env:USERPROFILE\Music\dsh-music" -Recurse -Filter *.wav |
  Sort-Object LastWriteTime -Descending | Select-Object -First 10 FullName, LastWriteTime
```

### 5. `未找到 dsh-soundcheck 引擎；先装插件或设置 MUSIC_SOUNDCHECK_ENGINE`

**原因**：深分析功能依赖可选的 `dsh-soundcheck`，当前机器没装，也没设环境变量。

**处理**：装 soundcheck 插件，或指向它的可执行文件；只做普通分析时不要加 `deep`。

```powershell
$env:MUSIC_SOUNDCHECK_ENGINE = "C:\path\to\dsh-soundcheck.exe"
```

## 工程与曲风

### 6. `工程不存在: C:\Users\...\Music\dsh-music\xxx\project.json`

**原因**：`project` 路径写错，或工程目录里没有 `project.json`。相对路径会先按当前目录找，找不到再拼到 `~/Music/dsh-music`。

**处理**：用绝对路径，或先确认目录里有 `project.json`。

```powershell
Get-ChildItem "$env:USERPROFILE\Music\dsh-music" -Directory |
  Where-Object { Test-Path (Join-Path $_.FullName 'project.json') } |
  Select-Object -ExpandProperty FullName
```

### 7. `缺少 project`

**原因**：这个工具必须带 `project` 参数，但你只传了 `op` 或其它参数。

**处理**：补上工程路径，例如 `project="C:\Users\你\Music\dsh-music\my-song"`。

### 8. `缺少 project.json: C:\...`

**原因**：`music_design` 这类工具要求目录里已有工程文件，空目录不行。

**处理**：先用 `music_project op=create` 建工程，再跑设计/导出。

```text
music_project op=create name="my-song" genre="citypop" bpm=110 bars=16
```

### 9. `没有曲风 {id}；可用: ...`

**原因**：`genre` 传了不存在的 id。可用值以报错里列出的为准（如 citypop、lofi、hiphop、house、rock、trap、cinematic 等）。

**处理**：换成报错列表里的 id；先列曲风再建工程。

```text
music_genres op=list
```

### 10. `不支持的 op：{op}`

**原因**：工具只认固定几个 `op`，传了别的字符串。

**处理**：看该工具的说明，改用 `get/add/set/...` 里的合法值。

## 渲染与 SoundFont

### 11. `找不到 fluidsynth`

**原因**：`fluidsynth` 不在 PATH，渲染 MIDI 时会直接失败。

**处理**：装 FluidSynth，或把它所在目录加到 PATH，然后**重开 DSH**。

```powershell
winget install --id FluidSynth.FluidSynth -e --accept-source-agreements --accept-package-agreements
where.exe fluidsynth
```

### 12. `fluidsynth 渲染失败（{name}）：{stderr}`

**原因**：FluidSynth 找到了但渲染失败。常见是 SoundFont 路径含特殊字符、MIDI 损坏、或输出目录不可写。

**处理**：先单独跑一次 fluidsynth 看 stderr；确认 SoundFont 能被加载。

```powershell
fluidsynth --help
Test-Path "$env:USERPROFILE\soundfonts\FluidR3_GM.sf2"
```

### 13. `SoundFont 不存在: C:\...\FluidR3_GM.sf2`

**原因**：鼓组渲染固定要 FluidR3_GM.sf2，但候选路径都没有这个文件。

**处理**：把 `FluidR3_GM.sf2` 放到 `%USERPROFILE%\soundfonts\`，或用 `MUSIC_SOUNDFONT` 指定绝对路径。

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\soundfonts" | Out-Null
Copy-Item "D:\你的\FluidR3_GM.sf2" "$env:USERPROFILE\soundfonts\FluidR3_GM.sf2"
$env:MUSIC_SOUNDFONT = "$env:USERPROFILE\soundfonts\FluidR3_GM.sf2"
```

### 14. `轨 {tid} 指定了采样器 {sid}，但工程里没有这个采样器定义`

**原因**：工程的 track 写了 `sampler: "<id>"`，但 `samplers` 里没有这个 id。

**处理**：先用 `music_sampler op=set` 注册采样，再渲染；或删掉该轨的 `sampler` 字段。

```text
music_sampler op=set sampler={id:"kick01", file:"C:\samples\kick.wav", mode:"oneshot"}
```

## 混音、母带与总线

### 15. `没有可混的分轨；先 music_render`

**原因**：`music_mix` 去 `audio/render-v1`（或 `renders.current`）找分轨，但目录是空的。

**处理**：先渲染，再混音；不要直接跳到 mix。

```text
music_render project="C:\Users\你\Music\dsh-music\my-song"
music_mix project="C:\Users\你\Music\dsh-music\my-song"
```

### 16. `需要 project 或 stems`

**原因**：`music_mix` 既没收到工程路径，也没收到分轨字典。

**处理**：二选一：传 `project`，或传 `stems={drums:"...", bass:"..."}`。

### 17. `总线路由成环：...`

**原因**：`music_bus` 里把 A 送到 B、B 又送回 A，形成环路。

**处理**：用 `music_bus op=list` 看清路由，拆掉一条父总线。

```text
music_bus project="my-song" op=list
music_bus project="my-song" op=route track="drums" bus="mix"
```

### 18. `不认识的自动化参数：{param}`

**原因**：自动化只支持 `gain` / `pan` / `lowpass` / `highpass`，传了别的名字。

**处理**：改成这四个之一；参数写错不会“差不多能用”，会直接报错。

```text
music_automation project="my-song" op=set lane={track:"keys", param:"gain", points:[{bar:1,value:0},{bar:9,value:-4}]}
```

### 19. `points 至少一个断点`

**原因**：自动化曲线没有断点，等于没画。

**处理**：至少给一个 `{bar, value}`，通常给两个才能形成变化。

### 20. `需要 mix 路径或 project`

**原因**：`music_master` 既没拿到 `mix` 文件，也没拿到工程。

**处理**：先 `music_mix` 产出 `audio/mix/mix-v1.wav`，再 master；或直接传 `mix` 绝对路径。

```text
music_master project="my-song" preset="pop" targetLufs=-10
```

### 21. `读不到输入响度（缺 pyloudnorm/soundfile）`

**原因**：母带需要测 LUFS，但 venv 里缺 `pyloudnorm` 或 `soundfile`。

**处理**：补装两个包，再重跑母带。

```powershell
& "$env:USERPROFILE\.local\share\dsh-music\venv\Scripts\python.exe" -m pip install pyloudnorm soundfile
```

## 人声（肥鱼 9880）

### 22. `连不上声音服务 http://127.0.0.1:9880：...`

**原因**：肥鱼声音服务没启动，或端口不对。人声、和声、调教都依赖它。

**处理**：启动服务；确认 `/health` 能打开；再看插件配置里的 `voiceBaseUrl`。

```powershell
powershell -ExecutionPolicy Bypass -File ".\scripts\setup_voice_service.ps1"
Invoke-WebRequest -UseBasicParsing http://127.0.0.1:9880/health
```

### 23. `声音服务 HTTP {code}: {detail}`

**原因**：服务在跑，但这次请求被拒（鉴权、参数、模型未加载等），`detail` 是服务端原文。

**处理**：按 `detail` 处理；401/403 先检查 API Key，404 检查服务版本。

### 24. `读不到声音服务 API Key；配置 voiceApiKeyFile 或先部署服务`

**原因**：服务要求鉴权，但插件找不到 key 文件。

**处理**：在 DSH 配置里写 `voiceApiKeyFile`，指向服务生成的 key 文件。

```text
music_doctor
```

### 25. `声音任务 {job_id} {status}: {error}`

**原因**：人声合成任务失败或超时。CPU 上 20 秒人声要 5–6 分钟，长歌更容易超时。

**处理**：用同一个 `jobId` 继续查，不要重复提交；先缩短到一段试。

```text
music_vocals project="my-song" section="chorus" wait=false
```

### 26. `没有歌词；先 music_lyrics`

**原因**：还没写歌词就让人声开唱。

**处理**：先写歌词并校验，再唱。

```text
music_lyrics project="my-song" op=set text="第一句\n第二句"
```

### 27. `没有 midi/vocal-harmony.mid；先 music_harmony 排和声`

**原因**：选了 `part=harmony`，但还没生成和声 MIDI。

**处理**：先排和声，再唱和声。

```text
music_harmony project="my-song" op=plan strategy=third_below
```

### 28. `找不到谱面：analysis/vocal-align.json 或 midi/vocal.mid`

**原因**：调教需要人声谱面，但工程里两者都没有。

**处理**：先 `music_vocals` 唱出人声（会生成对齐文件），或至少 `music_compose track=vocal` 生成旋律。

```text
music_compose project="my-song" track="vocal"
music_vocals project="my-song"
```

### 29. `只支持 svp / vsqx`

**原因**：`music_tunefile` 只认 Synthesizer V 的 `.svp` 和 VOCALOID 4 的 `.vsqx`。

**处理**：换格式导出/导入；不要传 `.ustx`、`.mid`。

## 分析、Remix 与音效库

### 30. `音频不存在: C:\...\xxx.wav`

**原因**：路径写错，或文件被移动/删除。

**处理**：用绝对路径，先 `Test-Path` 确认。

```powershell
Test-Path "C:\path\to\audio.wav"
```

### 31. `音频是空的`

**原因**：输入音频 0 字节，或解码后没有采样。

**处理**：换一个能正常播放的文件；用 ffprobe 看时长。

```powershell
ffprobe -hide_banner "C:\path\to\audio.wav"
```

### 32. `未知模式 {mode}；可用 remix / cover / rearrange`

**原因**：`music_remix` 的 `mode` 写错。

**处理**：只用 `remix`、`cover`、`rearrange` 三个值。

### 33. `缺少 input（要 remix 的音频路径）`

**原因**：没传 `input`。

**处理**：补上音频绝对路径。

```text
music_remix input="C:\path\to\song.mp3" mode="remix" brief="citypop 复古"
```

### 34. `需要 rubberband 才能变调；先 apt-get install rubberband-cli`

**原因**：Remix 目标调性和原曲不同，需要 Rubber Band 做变速不变调/变调；当前环境没有。

**处理**：保持原调（去掉 `key` 参数），或安装 Rubber Band 后重试；Windows 上先确认 `where.exe rubberband`。

```powershell
where.exe rubberband
```

### 35. `音频分析超时（>{timeout}s）：{name}`

**原因**：深分析（分轨/ASR）超时；CPU 机器上很常见。

**处理**：缩短分析段（`start`/`end`），或改用 `deep=false` 的快速分析。

```text
music_analyze audio="C:\path\to\audio.wav" deepStems="off" start="0:00" end="0:30"
```

### 36. `目录不存在：{p}`

**原因**：音效库的根目录路径不存在。

**处理**：先建目录，或改成现有目录。

```powershell
New-Item -ItemType Directory -Force "D:\Samples" | Out-Null
```

### 37. `库里找不到：{...}`

**原因**：搜索条件太严，或这个根还没扫描。

**处理**：先 `scan`，再放宽条件；星级/时长过滤会筛掉很多。

```text
music_library op=scan root="D:\Samples" maxSeconds=20
music_library op=search q="kick"
```

### 38. `export 需要 dest（目标目录）`

**原因**：导出音效库时没给目标目录。

**处理**：补 `dest`，并确认目录可写。

```text
music_library op=export ids=["abc123"] dest="D:\Exports"
```

### 39. `工程还没有可预览的音频；先 render/mix/master`

**原因**：预览要找 `audio/` 下的成品，但还没渲染。

**处理**：先 render / mix / master，再 preview。

```text
music_render project="my-song"
music_preview project="my-song"
```

### 40. `波形生成失败：...`

**原因**：预览绘图失败，常见是音频损坏或 ffmpeg 不可用。

**处理**：先确认音频能播放，再跑 doctor 看 ffmpeg。

```powershell
ffmpeg -hide_banner -i "C:\path\to\mix.wav" -f null -
```

## 编曲、采样器与效果链

### 41. `add 需要 notes`

**原因**：`music_notes op=add` 没给音符数组。

**处理**：给 `notes=[{pitch:60, bar:1, beat:1, dur:1, velocity:100}]`。

### 42. `capture 需要 name`

**原因**：抓 pattern 时没给名字。

**处理**：补 `name`，例如 `name="verse"`。

### 43. `第 {start}–{end} 小节没有音符可以抓`

**原因**：指定的区间里轨是空的。

**处理**：换区间，或先确认这条轨有音符。

```text
music_notes project="my-song" track="keys" op=get
```

### 44. `没有这个 pattern：{pid}`

**原因**：pattern 名写错或已被删。

**处理**：先列 pattern 再摆。

```text
music_patterns project="my-song" op=list
```

### 45. `playlist 是空的，先用 place 摆 pattern`

**原因**：还没把 pattern 放到 playlist 就执行 `apply`。

**处理**：先 `place`，再 `apply`。

```text
music_patterns project="my-song" op=place pattern="verse" startBar=1 repeat=2
music_patterns project="my-song" op=apply
```

### 46. `没有这个采样器：{id}（先 sampler set）`

**原因**：给轨指定了不存在的采样器 id。

**处理**：先注册采样器；名字要完全一致。

```text
music_sampler op=set sampler={id:"kick01", file:"C:\samples\kick.wav", mode:"oneshot"}
```

### 47. `采样文件不存在：{path}`

**原因**：采样器指向的音频被移动/删除。

**处理**：把文件放回原路径，或重新 `sampler set` 指向新路径。

### 48. `工程里没有这条轨：{tid}`

**原因**：轨 id 写错；可用 id 在 `project.json` 的 `tracks[].id` 里。

**处理**：先打开工程看轨 id，再操作。

```powershell
Get-Content "C:\Users\你\Music\dsh-music\my-song\project.json" -Raw |
  ConvertFrom-Json | Select-Object -ExpandProperty tracks | Select-Object id
```

### 49. `没有这个预设：{name}（有 ...）`

**原因**：效果链预设名不在列表里。

**处理**：用报错里列出的名字；当前有 `vocal-clean / keys-air / drum-punch / guitar-bite / bass-tight`。

### 50. `不认识的 type：{t}（可选 ...）`

**原因**：效果链类型写错。

**处理**：用报错列表里的类型：`gain / highpass / lowpass / eq / comp / saturate / chorus / delay / reverb / limiter / widen`。

## 导出与第三方工程

### 51. `文件不存在: {p}`

**原因**：导入 `.svp/.vsqx` 时路径写错。

**处理**：用绝对路径，并确认扩展名是 `.svp` 或 `.vsqx`。

```powershell
Test-Path "C:\path\to\song.svp"
```

### 52. `这个工程文件里没有音符`

**原因**：第三方工程是空的，或音符在别的轨/片段里，导出器没读到。

**处理**：先在 Synthesizer V / VOCALOID 里确认主旋律轨有音符，再导出。

### 53. `系统没有可用的 WASAPI 回环设备`

**原因**：`music_listen` 要采集系统正在播放的声音，但 Windows 没开立体声混音/回环。

**处理**：在「声音设置 → 录制」里启用「立体声混音」，或改用 `grab` 之外的输入文件。

```powershell
Get-CimInstance Win32_SoundDevice | Select-Object Name, Status
```

### 54. `没有找到回环/监视设备（macOS 请先装 BlackHole）`

**原因**：macOS 上没装虚拟回环设备；Windows 上是录音设备被禁用。

**处理**：macOS 装 BlackHole；Windows 启用立体声混音后重试。

## 其它

### 55. `无法识别的调性: {text}`

**原因**：调性写成 `A minor`、`Am7` 之类解析器不认的格式。

**处理**：用 `Am`、`C`、`F#m` 这种「音名 + 可选 m」；不要带和弦性质。

### 56. `无法识别的音名: {name}`

**原因**：音名不是 `C4` / `F#3` / `Bb2` 这种格式。

**处理**：改成「字母 + 可选升降号 + 八度」。

### 57. `无法识别的和弦: {symbol}`

**原因**：和弦符号不是罗马数字级数（如 `I`、`V7`、`vi`、`V7/ii`）。

**处理**：用级数写法；不要写 `Cmaj7` 这种绝对和弦名。

### 58. `读不到输入响度（缺 pyloudnorm/soundfile）`

**原因**：见第 21 条；venv 缺测量库。

**处理**：补装依赖后重跑 master。

## 还是解决不了

1. 跑一次完整体检：`powershell -ExecutionPolicy Bypass -File ".\scripts\doctor.ps1"`，把 ❌ 项按修复命令处理。
2. 带上三样东西发售后：**完整报错原文**、`%USERPROFILE%\.dsh\music\engine.log` 最后 80 行、`doctor.ps1 -Json` 的输出。
3. 不要删 `project.json` 和 `midi/` 目录——它们是复现问题的最小材料。
