# DSH Music 1.0.2

发布日期：2026-11-09

这是一次「交付可靠性」更新，功能与 1.0.1 相同，修的是「拿到手装不上 / 第一次渲染就报错」的两类问题。

## 修了什么

### 1. 缺 FluidR3 音源时，渲染不再直接失败

以前鼓轨固定用 `FluidR3_GM.sf2`，没装这个 141 MB 音源时 `music_render` 会抛 `SoundFont 不存在`，第一次「编曲 + 渲染」就卡住。

现在：鼓优先用 FluidR3；找不到就自动回退到包内的 `GeneralUser.sf2`，鼓照样出声（鼓组音色略少一点）。`music_render` 的返回值多了 `drumSoundfont` 字段，`report/render-v1.json` 里也会写清楚用的是哪一个。

只有两个音源都找不到时才会报错，报错信息会直接告诉你把 `GeneralUser.sf2` 放到 `%USERPROFILE%\soundfonts\`，或设 `MUSIC_SOUNDFONT_MELODIC`。

### 2. 中文路径安装不再写坏依赖

旧版安装脚本把 tgz 的绝对路径直接交给 `dsh plugin add`。当解压目录或用户名带中文（例如 `C:\Users\张三\下载\`）时，Windows PowerShell 5.1 会按 ANSI 传参，装完 profile 的 `dependencies` 里留下乱码路径，后面 `pnpm install` 就找不到包。

现在安装脚本先把 tgz 复制到 `C:\Users\Public\dsh-music-stage-<pid>\`（纯 ASCII）再安装，装完清理。

### 3. 面板（输入框上方那条「♪ 音乐」）现在随包一起装

1.0.1 及以前只发插件本体，装完只有工具，没有输入框上方那条面板——但介绍视频和 README 都在讲这个面板。

1.0.2 的交付包里多了 `dsh-music-panel-0.5.1.tgz`，`install.ps1` 会把它一起装进 profile 并加进 `dsh.profile.bundles`。装完重启 DSH，输入框上方就有：

- 收起态一条：工程 / 曲风 / BPM / 调性 / 小节 / 歌手 + 「编曲」「展开」「隐藏」
- 展开态：系统输出、混音台（总分组 / 鼓组 / 贝斯 / 键盘铺底 / 吉他，各带推子与 FX 链）、音效库
- 「隐藏」把整条收成一个「♪ 音乐」小胶囊，刷新后仍保持隐藏；点胶囊恢复

面板连的是本机引擎（`127.0.0.1:17890`，占用时自动换端口并写 `~/.dsh/music/engine.json`）。

## 升级方法

已经装了 1.0.1 的话，两个办法任选：

1. 重新跑交付站下载的新 `dsh-music-1.0.2.zip` 里的 `一键安装.cmd`（会覆盖 `file:` 依赖并补装面板）
2. 手动：`dsh plugin --profile <你的 profile> add "C:\...\dsh-music-1.0.2.tgz"`，再 `add` 一次面板包

工程、音效库、profile 里的其它插件都不会被动。

## 升级后自检

```
music_doctor
```

看到 `engine: ok 1.0.2` 就对了。再跑一次 `music_render`，如果没装 FluidR3，返回里的 `drumSoundfont` 会写 `GeneralUser(回退)`——这是正常的，不是错误。

## 已知问题

- 声音服务（人声/唱歌）要单独起，没起时 `music_vocals` 会报 `voice 服务 unreachable`，不影响器乐。
- 首次安装仍然要下载 Python 依赖（约 300 MB），10–20 分钟，取决于网速。
- 面板的「隐藏」状态存在浏览器 localStorage，换机器不会跟随。
